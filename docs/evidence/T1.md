## Attribution (A3)

Method implemented in `send`/`waitForTurn`:
1. Before submitting, count the turn containers `[data-xid="aim-mars-turn-root"] > [data-tr-rsts]` (N). A tab without the turn root is a first turn (N = 0).
2. Submit. Delivery is `yes` only when container index N exists and its query bubble label equals `"Copy " + text` (whitespace-normalised) within 15 s; otherwise `uncertain` (never resent).
3. `waitForTurn` only inspects container N and re-checks its query label on every poll; the answer is read from that container's `main-col`.

Observed (Q2 recorder, 100 ms polling, times from recorder start):
- 2317 ms Enter pressed; 2406 ms container count 1 → 2, new last container carries `Copy How long would it take to hard-boil an egg there, compared with at sea level?`, and it has no answer node yet (`ans: false, ansLen: 0`).
- The earlier turn stayed in container 0 with its full answer and footer (class `tonYlb Uphzyf`; the new container has `tonYlb` only). So the stale answer remains visible while the new turn starts; reading "the last answer on the page" before the new container appears would return it, which the index + query check prevents.
- Q3/Q4 through `src/page.js`: `delivered: yes` after 678 ms (navigation) and 113 ms (input) respectively; `turnId.index` 0 and 1.

Unproven: identical repeated prompts in one thread (index still distinguishes them, but not tested); very long or multi-line prompts (label equality not tested beyond ~130 chars); DOM replacement of an existing container (not observed).

## Extraction and citation mapping (A4, FR-5.1/5.2)

Chip structure (sanitized, from Q1):

```html
<span class="NMq1me"><span aria-hidden="true">&nbsp;</span>
  <a class="PMDqCb" aria-label="MadSci Network (+1) – Re: What is the boiling point of water on top of Mount Everist. Related results"
     href="https://www.madsci.org/posts/archives/2000-12/976811375.Es.r.html"></a>
  <button data-icl-uuid="…" aria-label="(same label)">…favicon, "MadSci Network", "+1"…</button></span>
```

Mapping implemented in `extract` (runs in the page):
- A chip is a `button[data-icl-uuid]`; its source is the sibling `a[href]`. The marker `[n]` is emitted at the chip's position in the text. `n` is assigned in order of first appearance per URL; a repeated URL reuses its marker.
- Title = the `aria-label` after the first ` – `, without the trailing `Related results`; URL = `a.href`.
- `(+N)` means the chip groups N more sources. Only the first (linked) source is in the DOM; the extra N are **not** extracted.
- Icon-only chips (`aria-label="Related results"`, no `a[href]`): no source exists in the DOM. In Q2 (1 chip) and Q4 (all 11 chips) they were `visibility: hidden`, so nothing is shown to the user; they are skipped. In Q1 two such chips were **visible**; they are skipped and counted in `unresolved` (Q1: 2). Their sources would need a UI interaction (not attempted; unproven).
- `main-col` parts skipped: footer `[data-xid="Gd7Hsc"]`, `[data-ignore-copy]`, `aria-hidden="true"`, `display: none`.
- Markdown: text blocks → paragraphs, `role=heading` → `###`, `ul/ol/li` → lists, `table` → pipe table, `strong`/`em` → `**`/`_`. `pre`/`code`/plain links and nested lists are implemented generically but **did not occur** in the four answers (unproven against Google's DOM).
